## 1. 프로젝트 개요
Python 기본 문법과 객체 지향 프로그래밍(OOP) 설계를 활용하여 만든 CLI(콘솔) 기반의 퀴즈 게임 프로그램입니다.  
프로그램을 종료하고 다시 실행해도 사용자가 추가한 퀴즈와 최고 점수, 게임 플레이 이력이 그대로 유지되도록 파일 시스템(state.json, history.txt)을 통해 데이터 영속성(Persistence)을 보장하며, 견고한 예외 처리로 어떤 비정상적인 입력에도 프로그램이 크래시되지 않도록 설계했습니다.

## 2. 퀴즈 주제와 선정 이유
- 선정 주제: '나를 소개합니다'
- 선정 이유: 개발자 본인의 정체성과 대학 생활, 그리고 주요 관심사를 퀴즈에 담아 나라는 인물을 사람들에게 소개하고자 위와 같은 주제를 선정했습니다.

## 4. 핵심 기능 및 설계 의도
**1. 퀴즈 풀기 (랜덤 출제 및 힌트 시스템)**
- 기능: 사용자가 원하는 문제 수를 선택하면, 전체 퀴즈 중 무작위로 추출하여 출제합니다. 힌트를 사용할 경우 획득 가능한 기본 점수(10점)가 절반(5점)으로 차감됩니다.
- 설계 의도(왜 이렇게 짰는가?): 
  - 원본 퀴즈 리스트를 직접 섞지 않고 random.sample()을 사용해 사본을 추출했습니다. 원본 데이터의 순서를 훼손하지 않기 위함입니다.
  - 점수 차감을 단순한 뺄셈이 아닌 point라는 배점 변수를 두어 유연하게 관리함으로써, 로직이 꼬이는 것을 방지했습니다.

**2. 퀴즈 추가**
- 기능: 문제, 선택지 4개, 정답 번호(1~4), 힌트를 입력받아 새로운 퀴즈를 동적으로 등록하고 파일에 즉시 저장합니다.

**3. 퀴즈 삭제**
- 기능: 등록된 퀴즈 목록을 보고 번호를 선택해 삭제할 수 있습니다.
- 설계 의도: 파이썬의 del 키워드를 사용해 리스트의 특정 인덱스를 지우고, 변경된 리스트 전체를 즉시 JSON 파일에 덮어써서 메모리와 저장소의 데이터를 동기화했습니다.

**4. 퀴즈 목록**
- 기능: 현재 등록된 모든 퀴즈의 문구와 목록을 보기 쉽게 번호와 함께 출력합니다.

**5. 점수 및 기록 확인 (Upgraded)**
- 기능: 현재까지 기록된 역대 최고 점수와, 과거에 플레이했던 모든 게임의 날짜/시간, 푼 문제 수, 획득 점수 이력을 출력합니다.
- 설계 의도: JSON 파일이 아닌 history.txt에 누적 기록(Append 모드) 방식을 채택하여, 이전 기록이 지워지지 않고 계속 쌓이도록 설계했습니다.

**6. 예외 및 안전 처리**
- 기능 및 설계 의도: 
  - safe_input()이라는 전담 함수를 만들어 while True와 try-except 구조로 묶었습니다. 빈칸(엔터), 스페이스바, 문자열, 범위 밖 숫자 등 어떤 예외가 들어와도 프로그램이 종료되지 않고 재입력을 유도합니다.
  - Ctrl + C 또는 강제 종료(EOFError) 발생 시, except 구문에서 이를 캐치하여 데이터를 마지막으로 안전하게 저장한 뒤 종료되도록 최후의 방어선을 구축했습니다.

## 6. 데이터 파일 설명 (state.json)
- 저장 위치: 프로젝트 루트 디렉터리 (/state.json)
- 인코딩 설정: UTF-8 (한글 텍스트 깨짐 방지)
- 동작 방식: 
  - 프로그램 실행 시 해당 파일이 없거나 손상된 경우, 기본 5개 문제로 자동 복구됩니다.
  - 데이터 변경 시 메모리에 있는 전체 상태를 JSON 파일에 덮어쓰기(Overwrite) 합니다.
- 하위 호환성 유지(설계 의도): 구버전 데이터 파일에 hint 필드가 없더라도 에러가 발생하지 않도록 딕셔너리의 .get("hint", "기본값") 메서드를 활용해 프로그램의 호환성을 높였습니다.
- 데이터 스키마 구조:
```json
{
  "quizzes": [
      {
          "question": "나의 롤 최고 티어는?",
          "choices": [
              "다이아몬드",
              "마스터",
              "그랜드마스터",
              "챌린저"
          ],
          "answer": 4,
          "hint": "가장 높은 티어입니다."
      }
  ],
  "best_score": 100
}
```

## 7. 시스템 설계 및 기술적 의도 (설계 철학)

**7.1 객체 지향 프로그래밍(OOP) 도입 이유**
데이터(문제, 보기, 정답)와 그 데이터를 다루는 로직을 뿔뿔이 흩어진 함수로 관리하면 데이터 무결성이 깨지기 쉽습니다. 이를 Quiz라는 단일 객체로 캡슐화(Encapsulation)하여 데이터 관리를 직관적으로 만들었으며, 전체 흐름은 QuizGame 클래스가 통제하도록 책임을 분리했습니다. 

**7.2 주요 로직 분리 (관심사의 분리)**
유지보수를 위해 역할별로 로직의 진입점을 명확히 분리했습니다.
- Quiz 클래스: 데이터 모델 로직 (직렬화 및 역직렬화, 문제 출력)
- QuizGame 클래스: 상태 관리 및 게임 진행 로직 (파일 I/O, 메인 루프, 점수 계산)
- safe_input(): 공통 유틸리티 로직 (사용자 입력 검증 및 예외 처리 전담)

**7.3 JSON 저장 방식 채택 이유**
파이썬의 핵심 자료구조인 리스트(List)와 딕셔너리(Dict)를 1:1로 가장 쉽게 매핑할 수 있기 때문입니다. 또한 사람이 직접 텍스트 파일을 열어서 읽고 수정하기 편한 가독성(Human-readable)을 가지고 있으며, 별도의 외부 라이브러리 설치 없이 가볍게 구현할 수 있어 채택했습니다.

## 8. 프로젝트 확장성 및 한계점 분석

**8.1 대용량 데이터 처리의 한계 (1000개 이상 누적 시)**
현재의 JSON 덮어쓰기 방식은 퀴즈가 1,000개 이상으로 늘어날 경우 심각한 성능 저하를 유발합니다. 단 1개의 퀴즈만 지워도 999개를 텍스트로 재변환하여 하드디스크에 기록(I/O 과부하)해야 하며, 메모리 낭비가 심합니다. 향후 대량의 데이터를 다루게 된다면 특정 데이터만 빠르게 색인(Index)하고 수정할 수 있는 내장 데이터베이스(SQLite 등)로 마이그레이션 해야 합니다.

**8.2 데이터 백업 및 복구 전략**
파일 덮어쓰기(Write) 동작을 수행하는 찰나의 순간에 강제 종료가 발생하면 파일 내용이 모두 날아가는 원자성(Atomicity) 결여 문제가 있습니다. 이를 보완하기 위해 추후 파일 저장 직전 기존 데이터를 state.json.bak 이라는 임시 파일로 복사해 두는 백업 복원 절차를 도입할 계획입니다.

## 9. 유지보수 및 협업 가이드

**9.1 요구사항 변경 시 수정 포인트 안내**
- 문제 배점이나 힌트 차감 점수를 바꾸고 싶다면: QuizGame 클래스의 play_quiz() 메서드 내부의 point 변수 로직을 수정해야 합니다.
- 퀴즈에 새로운 정보(예: 난이도 설정)를 추가하고 싶다면: Quiz 클래스의 __init__, to_dict(), from_dict() 세 군데 모두에 속성을 추가로 업데이트해야 합니다.

**9.2 Git 브랜치 활용 및 커밋 규칙**
안정적인 협업을 위해 아래의 전략과 커밋 규칙을 준수합니다.
- 브랜치 전략: 
  - main: 언제든 실행 가능한 안정적인(Stable) 버전만 유지합니다.
  - feature/...: 새로운 기능(예: feature/hint-system)을 개발할 때 파생시키는 브랜치입니다. 완료 및 테스트 후 main으로 병합(Merge)합니다.
- 커밋 규칙 (Prefix 활용):
  - feat: 새로운 기능 추가
  - fix: 버그 수정 및 예외 처리
  - docs: README 등 문서 수정
  - refactor: 코드 구조 및 로직 개선 (기능 변화 없음)
